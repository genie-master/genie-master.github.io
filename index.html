GenieMaster: An Embodied Continual Harness for Persistent Multi-Robot Work

How can a general-purpose agent keep robots useful after the first action, the first task, or the first failure? GenieMaster connects high-level reasoning to responsive, closed-loop execution through a shared interface for guidance, feedback, and task continuity.

01Why this problem

The deployment gap

Robots need more than a plan.

Frontier agents can reason about unfamiliar tasks and objects, while learned policies can react at the timescale of physical contact. A deployed system needs both. It must turn broad reasoning into signals a policy can use, then decide what actually happened after the action.

That loop becomes harder when work persists. Requests arrive dynamically, a higher-priority task interrupts the current one, and one robot's progress can determine whether another robot can proceed. A system that forgets unfinished work at every boundary cannot coordinate reliably.

The central question is not only what action to take, but how to keep useful work going after the world responds.
02What GenieMaster adds

Core features

Three interfaces make continual work possible.

GenieMaster is organized around the information that must cross the boundary between an agent and a robot. Each feature addresses a different failure mode in long-running execution.

01

Multimodal policy guidance

The agent can provide detailed language, spatial cues, and object reference images. These are not post-hoc annotations: the policy is trained to interpret the same guidance representations it receives during deployment.

02

Bidirectional execution feedback

Observations, progress, success, and error evidence return to the agent. The agent can advance a subtask, revise its guidance, or trigger recovery instead of assuming that an action succeeded.

03

Persistent task state and memory

Assignments, dependencies, unfinished work, and execution experience are retained. Temporary memory supports ongoing tasks, while asynchronous reflection turns experience into reusable context for later orchestration.

03How it works

Embodied Execution Protocol

A stable contract between reasoning and action.

The protocol exposes capabilities through shared tool descriptions, input parameters, and result contracts. Domain interfaces describe task semantics and business context; embodiment interfaces bind those tasks to robot instances and execution services.

The coding agent composes execution requests, receives physical evidence, and keeps task context available across invocations. This separation lets the harness coordinate heterogeneous robots without changing the high-level task interface.

04What the policy sees

Agent-policy co-design

Context only helps when the policy can use it.

An agent may identify a product from a catalog, locate an interaction point, or describe a safer approach. GenieMaster aligns demonstrations, annotations, and VLA training around those same inputs, so acquired context becomes executable behavior.

Spatial cues

Boxes, points, and trajectories localize the target and the intended interaction in the current camera view.

Object references

A reference image grounds a request in a product or object that may be absent from the training distribution.

Detailed language

Execution descriptions expose order, arm assignment, approach direction, and contact constraints.
