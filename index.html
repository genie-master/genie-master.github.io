00At a glance

GenieMaster

An interface that lets a coding agent work in the physical world.

GenieMaster connects a coding agent to responsive robot policies through an Embodied Execution Protocol. The agent composes capabilities, supplies context that a policy can use, reads physical feedback, and keeps unfinished work alive across tasks, robots, and interruptions.

The system combines capability invocation, guidance, feedback, and continuity with continual harness adaptation. Reflection and memory improve later guidance, assessment, and orchestration while the deployed model parameters remain fixed.

01The execution protocol

Embodied Execution Protocol

One interface for reasoning, action, and what happens next.

EEP is the agent–embodiment interface at the center of GenieMaster. It lets a coding agent invoke robot capabilities, provide context that a policy has learned to use, inspect physical outcomes, and carry unfinished work across invocations and robots.

The protocol is inspired by the tool abstraction of Model Context Protocol (MCP). Domain workflows express task semantics; embodiment implementations bind those workflows to robot instances, calibration, and execution services. Shared descriptions, parameters, and result contracts keep orchestration extensible.

The four contracts describe the information that must cross the boundary between the agent and the physical world. Guidance and Feedback form a bidirectional agent–policy interface; Continuity and memory keep work moving over time.

02EEP contracts

Capability / Guidance / Feedback / Continuity

Four contracts make persistent execution legible.

Each contract answers a different question: what can the system do, what should the policy use, what physically happened, and what must remain true when the next task arrives?

01

Capability

Domain tools compose workflows such as navigation, pick, and place. Embodiment tools connect those operations to a selected robot and its execution services.

The agent supplies detailed language, spatial cues, or object reference images alongside observations, robot state, and the subtask instruction.

Feedback

Observations, status, and success/error evidence return to the agent. The agent can advance, revise guidance, arrange another observation, or recover.

Evidence for progression and recovery

Assignments, progress, dependencies, and unfinished tasks persist across invocations. This supports coordination when work is interrupted or a robot changes.

03Continual harness adaptation

Co-design, reflection, and memory

Experience changes the next invocation while the policy stays responsive.

A policy cannot use context that it has never learned to interpret. GenieMaster co-designs the guidance interface, demonstration annotations, and VLA training, so spatial cues, object references, and detailed language become executable conditions rather than extra text.

Guide

The agent grounds an open-ended request in the current scene, a catalog, or an object reference.

Assess

Success and error context makes physical outcomes available for task progression and recovery.

Adapt

Reflection turns records into reusable guidance, assessment criteria, and orchestration context.

Temporary memory

Correct the work in front of you.

Recent execution records inform subsequent policy conditions, detector context, and task orchestration while a task is still active.

Long-term memory

Retain what is useful later.

Asynchronous reflection consolidates experience for later tasks and compatible robots. Deployment changes context and invocation behavior while model parameters remain fixed.

The harness evolves through the information it retains, not through a new model update for every physical mistake.
04Experiments

Evidence across the same execution loop

Each experiment isolates a part of persistent physical work.

We follow the paper's order: shared setup, end-to-end performance, capability composition, unseen-product generalization, learning from experience, LIBERO-Pro, and persistent deployment.

04.1 / Experimental setup and overall end-to-end performance

GenieMaster improves both task success and completion.

Across six real-world tasks, GenieMaster reaches 78.67% success rate (SR) and 89.71% task completion (TC). Human orchestration remains a useful upper reference, while the EEP harness substantially exceeds the vanilla VLA and dual-system baselines.

04.2 / Capability composition and control allocation

Adding capabilities makes longer tasks executable.

As the available capability set grows from C1 to C5, success rises from 25% to 97%. Domain workflows compose reusable tools, while the harness allocates subtasks to the robot that can execute them.

04.3 / Unseen-product generalization through in-context guidance

Visual references let the policy use knowledge at execution time.

With EEP-guided object references, novel-product retrieval improves from 12% at 10 training SKUs to 92% at 1,000. A separately trained text-only policy reaches 20% at the same scale, showing why agent-provided guidance must be aligned with policy training.

04.4 / Learning from experience

Reflection improves assessment and orchestration over time.

Reflection improves completion-boundary alignment for six of seven detectors. With accumulated memory, orchestration success rises from 28.6% in round one to 85.7% in round five, while tool use remains in the same operating range.

04.5 / Evaluation on LIBERO-Pro

The same harness transfers to a benchmark setting.

Across Spatial, Object, Goal, and LIBERO-10 under position-swap and task perturbations, GenieMaster reaches 60.38% success, a 49.6-point gain over the listed 10.75% policy baseline. Mean execution time is 22.4 seconds.

04.6 / Persistent deployment in a convenience store

EEP keeps a live operation moving as requests arrive.

In a 24-hour convenience-store deployment, scheduled inspections trigger restocking, customer orders trigger retrieval, and the agent assigns available capable robots. Task state and feedback let the system resume work and route follow-ups through the same contracts used in the controlled experiments.
