00At a glance

GenieMaster

An interface that lets a coding agent work in the physical world.

GenieMaster connects a coding agent to responsive robot policies through an Embodied Execution Protocol. The agent composes capabilities, supplies context that a policy can use, reads physical feedback, and keeps unfinished work alive across tasks, robots, and interruptions.

The system combines capability invocation, guidance, feedback, and continuity with continual harness adaptation. Reflection and memory improve later guidance, assessment, and orchestration while the deployed model parameters remain fixed.

03The execution protocol

EEP / Embodied Execution Protocol

Embodied Execution Protocol (EEP)

EEP is the agent–embodiment interface at the center of GenieMaster. It lets a coding agent invoke robot capabilities, provide context that a policy has learned to use, inspect physical outcomes, and carry unfinished work across invocations and robots.

The protocol is inspired by the tool abstraction of Model Context Protocol (MCP). Domain workflows express task semantics; embodiment implementations bind those workflows to robot instances, calibration, and execution services. Shared descriptions, parameters, and result contracts keep orchestration extensible.

04EEP contracts

Capability / Guidance / Feedback / Continuity

Four contracts make persistent execution legible.

Each contract answers a different question: what can the system do, what should the policy use, what physically happened, and what must remain true when the next task arrives?

01

Capability

Domain tools compose workflows such as navigation, pick, and place; embodiment tools bind them to a selected robot, calibration, and execution service.

Task workflows / composed tools / robot capabilities
+

Example. A restocking request can compose shelf inspection, navigation, grasp, and placement tools. The workflow stays stable while the embodiment layer selects a robot and supplies its calibration and execution endpoint.

inspect_shelf → navigate_to → pick → place

02

Guidance

The agent supplies detailed language, spatial boxes or points, and object reference images alongside observations and the subtask instruction.

Language / spatial cues / object references
+

Spatial guidance. A box, point, or region tells the policy where the relevant object or target is in the current image. This turns “pick the red bottle” into a grounded condition.

Visual goal conditioning. A reference crop or image describes what the target should look like, allowing the policy to match an unseen product by appearance rather than by a fixed category name.

Detailed language. The agent can add constraints such as “grasp the neck, keep the label facing outward, and place it in the front row.”

03

Feedback

Current or recent observations, state, and success/error evidence return to the agent so it can progress, revise guidance, or recover.

Observations / state / success or error
+

Example. After a failed grasp, the result includes the latest frame, the attempted action, and an error reason. The agent can then retry with a new point, ask another robot to help, or mark the subtask for later recovery.

observation + action_result + failure_reason

04

Continuity

Robot assignments, progress, dependencies, and unfinished work persist across invocations, enabling coordination when a task is interrupted or a robot changes.

Assignments / progress / dependencies / unfinished work
+

Example. If a robot pauses after retrieving an item, the next invocation receives the task state, completed steps, held object, and remaining dependencies. Another available robot can continue without restarting the whole plan.

task_id + completed_steps + assigned_robot + pending_work

05Continual harness evolution

Reflection and memory consolidation

Continual harness evolution

GenieMaster evolves the context used to guide, assess, and orchestrate execution while model parameters remain fixed during deployment. Temporary memory stores textual execution records: task objectives, observation summaries, detector outputs, and success or failure outcomes. When execution fails, the system automatically appends summaries of likely causes.

Periodically or on demand, asynchronous reflection reviews records across robots, assessing execution outcomes and detector judgments against task objectives and observations. This process runs outside online monitoring and consolidates reusable guidance, assessment criteria, recovery steps, and coordination strategies into long-term memory. The agent uses these instructions to guide subsequent execution, assess completion, and coordinate work across compatible robots.

These lessons inform later capability selection and completion assessment; retained task state separately supports the continuation of unfinished work.

Experimental evaluation

06.1 / Experimental setup and overall end-to-end performance

Overall end-to-end performance

Across six real-world tasks, GenieMaster reaches 78.67% success rate (SR) and 89.71% task completion (TC). Human orchestration remains a useful upper reference, while the EEP harness substantially exceeds the vanilla VLA and dual-system baselines.

06.2 / Capability composition and control allocation

Capability composition and control allocation

As the available capability set grows from C1 to C5, success rises from 25% to 97%. Domain workflows compose reusable tools, while the harness allocates subtasks to the robot that can execute them.

06.3 / Unseen-product generalization through in-context guidance

Unseen-product generalization through in-context guidance

With EEP-guided object references, novel-product retrieval improves from 12% at 10 training SKUs to 92% at 1,000. A separately trained text-only policy reaches 20% at the same scale, showing why agent-provided guidance must be aligned with policy training.

06.4 / Learning from experience

Learning from experience

Reflection improves completion-boundary alignment for six of seven detectors. With accumulated memory, orchestration success rises from 28.6% in round one to 85.7% in round five, while tool use remains in the same operating range.

06.5 / Evaluation on LIBERO-Pro

Evaluation on LIBERO-Pro

Across Spatial, Object, Goal, and LIBERO-10 under position-swap and task perturbations, GenieMaster reaches 60.38% success, a 49.6-point gain over the listed 10.75% policy baseline. Mean execution time is 22.4 seconds.

06.6 / Persistent deployment in a convenience store

Persistent deployment in a convenience store

In a 24-hour convenience-store deployment, scheduled inspections trigger restocking, customer orders trigger retrieval, and the agent assigns available capable robots. Task state and feedback let the system resume work and route follow-ups through the same contracts used in the controlled experiments.
